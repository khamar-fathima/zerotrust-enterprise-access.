==================================================
1. PROBLEM STATEMENT
==================================================

Organizations face increasing cyber threats due to excessive
user privileges and weak access controls.

This platform implements Zero Trust principles using:

1. Role-Based Access Control (RBAC)
2. Multi-Factor Authentication (MFA)
3. Device Verification
4. Session Monitoring
5. Security Auditing

The objective is to ensure secure enterprise access through
continuous identity verification and least-privilege access.

This must be a WORKING application, not just a frontend
prototype or static dashboard.

7. MULTI-FACTOR AUTHENTICATION (MFA)
==================================================

Implement real TOTP-based MFA.

Features:

- MFA enrollment
- Generate authenticator QR code
- Six-digit OTP verification
- Compatibility with standard authenticator apps
- MFA activation and deactivation
- Single-use recovery codes

Authentication flow:

Step 1: Enter email and password
Step 2: Verify credentials
Step 3: Complete MFA
Step 4: Verify device
Step 5: Validate user role
Step 6: Grant authorized access

Do not issue a fully authenticated session before
all required verification stages are completed.

Store MFA secrets securely and encrypted at rest.

Store recovery codes as hashes.

Protect MFA setup and disabling operations with
appropriate reauthentication.

8. DEVICE VERIFICATION
==================================================

Implement a registered-device verification system.

When a user logs in from a new device:

- Detect that the device is unrecognized
- Create a pending device registration
- Display a device verification screen
- Require administrator approval
- Prevent access until approval is completed

Device information should include:

- Device name
- Browser
- Operating system
- Registration timestamp
- Last activity
- Approval status

Device statuses:

PENDING
APPROVED
REVOKED

Administrators can approve or revoke devices.

Use cryptographically secure device credentials,
store only their hashes server-side, and bind them
to the appropriate user.

Do not rely on browser fingerprinting or user-agent
information alone as device authentication.

Use secure cookies and appropriate expiration.

==================================================
11. ZERO TRUST ACCESS ENGINE
==================================================

Implement a reusable backend Zero Trust middleware.

For every protected request, validate:

1. Is the user authenticated?
2. Is the session active?
3. Has the required MFA verification been completed?
4. Is the device approved?
5. Is the user account active?
6. Does the user's current role have permission
   to access the requested resource?

If any required condition fails:

DENY ACCESS.

Record the denied attempt in security audit logs.

Return the appropriate HTTP error response.

Do not trust frontend-provided role information.

Revalidate authorization against server-side
records to ensure role changes and session
revocations take effect.

Follow the principle of least privilege.
